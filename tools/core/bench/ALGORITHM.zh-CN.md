# 量化图搜索与内存优化原理

QuantizedGraph 通用图层使用 SymQG 编码、旋转与距离核。
SymQG 名称对应 SymphonyQG；本文描述当前实现，不宣称与上游逐行相同，也不将工程收益视为论文原创性证明。
验证方法和结果见 [测试说明](TESTING.zh-CN.md)。数据集配置保留在原优化分支。

## Succinct 实现

`feat/quantized-graph-performance-exploration-succinct` 基于优化分支的 `1ff3c1a5` 精简封装与构建、加载路径。
FP32/FP16 共用一个实现对象；路由头、均值、变换与树结构在一次加载中校验，构建错误直接返回错误码。
移除未使用的接口和实验用 `QG_DEGREE`、`QG_BLOCK_MODEL` 环境变量入口；邻居数与 codec 通过正式构建配置指定。
图遍历只保留量化搜索实际调用的路径，移除未使用的精确搜索策略框架。
路由统一从索引加载，移除独立外部路由路径参数；底层仅适配仓库固定的 RaBitQ 版本。
已持久化的 native/global/low_rank codec、1/2/4 视图及历史单视图快照继续使用原有格式。
搜索中的 SIMD 距离核、桶队列、剪枝、精排下界和预取策略保持原实现；性能对照见测试说明。

## 搜索流程

1. `local_builder` 构建 HNSW，用数据库向量训练入口路由树及量化参数，生成量化邻接块后一起 dump；打开时直接恢复。
2. 将查询旋转、投影、量化，通过路由树选择一个实际图节点作为 layer 0 入口。
3. 在原图派生的量化邻接图上搜索，用完整维度的邻居编码批量估计距离，以桶队列安排扩展顺序。
4. 对已展开节点计算全维整数中心距离估计及精排下界。
5. 按下界排列候选，选择性读取完整维度的存储向量，以 FP32 计算距离并返回 Top-K。

**保留 FP32 精排计算。** 默认使用 FP32 存储；可选 FP16 存储在精排时按需展开，精排针对舍入后的存储值。
FP16 无法恢复原始 FP32 向量的舍入损失。入口投影只影响起点选择；邻居编码、中心估计和最终距离使用完整向量维度。
路由树的层级与 HNSW 的 layer 不同。路由关闭时使用默认入口；缺失模型不会由检索过程自动训练。

## 路由模型是怎样生成的

`QuantizedGraphRouterBuilder` 从数据库计算均值并选取锚点，在完整维度递归聚类，形成最多16叉的树。
Cosine 使用球面聚类，L2 使用均值聚类。叶子保存实际图节点的内部 ID；中心再经过旋转、投影和整数编码。
训练不读取查询或 ground truth，但搜索参数的选取使用了开发查询的召回反馈。

“模型”是聚类中心、树结构、均值和叶子 ID 等索引数据，不是神经网络。
`local_builder` 将其嵌入快照，检索不再接受独立的外部模型路径。
因为叶子使用内部 ID，模型必须与训练时的图快照配对，不能仅凭维度和节点数相同就替换。

## 构建时训练量化参数

`QuantizedGraph.Codec` 控制量化编码，和 `QuantizedGraphRouter` 的入口树是两组不同的数据。
`native` 保留原生 SymQG 编码；`global` 学习全局仿射中心；`low_rank` 进一步学习局部中心的低秩基。
三种方式均通过 `Persist: true` 保存量化块。配置不再传入外部码本路径。

训练从图的有效内部 ID 采样，使用与量化块构建相同的邻居选择规则，取 32 邻居及二跳数据库向量作为代理查询。
极小图的二跳样本不足时使用直接邻居；空图或非法数据返回错误。FP16 数据按需展开，训练和编码遵循实际存储坐标。
L2 的基准中心使用搜索时的 SQ8 重建值，cosine 使用原存储中心。采样中心均值记为 $\mu$。
这里的代理查询来自数据库，不是 benchmark 的测试查询，也不使用 ground truth。

设邻居残差 $r=x-c$、代理查询残差 $s=q-c$、$u=\mu-c$。拟合中心 $a_0=c+\lambda u$，
最小化旋转后径向量化误差的几何代理目标：

$$A(\lambda)=\|(r-\lambda u)\wedge(s-\lambda u)\|^2=A(0)+2B\lambda+C\lambda^2.$$

因此无需查询参数扫描即可取 $\lambda=\operatorname{clip}(-B/C,0,1)$，退化目标取零。
`CenterWeight` 再对拟合值做收缩，是可配置超参数，不按数据集名称分流。

低秩版本计算邻域均值相对 $a_0$ 的偏移 $\delta$，取未中心化二阶矩 $E[\delta\delta^T]$ 的主要特征向量 $U$。
它最小化 $E\|\delta-UU^T\delta\|^2$。每个邻接批次保存带缩放的 FP16 系数 $z$，中心为 $a=a_0+Uz$；
查询只计算一次 $U^Tq$，每批更新中心距离的成本与秩有关。

`Codebook: hadamard` 在构建时生成固定的 16 个反对称方向；`gaussian` 在构建时对标准高斯合成样本执行反对称 Lloyd 训练，
使用独立的合成验证样本选取三次初始化中的最好结果。随机旋转为高斯参考分布提供动机，不意味着结构化 Hadamard 具有任意数据上的精确高斯保证。
数据库训练得到的均值、中心权重和低秩基，以及生成的码本，都作为参数字节嵌入索引。
`Seed` 控制采样与 Gaussian 初始化；底层 SymQG 旋转沿用索引格式规定的固定规则。

训练和编码都在构建阶段完成，检索不读取训练配置、外部模型或 `QG_*` 环境变量。
不含量化块的历史索引仍走兼容的打开时编码流程。`local_builder` 在同一次调用中完成建图、训练、量化和保存；已有图可作为同一工具的 `InputIndex` 输入。数据集配置保留在原优化分支。
快照不可变，修改原向量或图结构后需要重建。持久化增加磁盘体积，消除重复编码，不等于零拷贝加载或降低全部索引内存。

## 全维整数中心与延后精排

中心量化重建为 $\hat x$，保存其重建误差大小。误差界的基础是：若
$\|x-\hat x\|\le\epsilon$，则由 Cauchy–Schwarz 不等式，

$$|q^Tx-q^T\hat x|\le\|q\|\epsilon.$$

对平方 L2，由三角不等式有

$$\|q-x\|^2\ge\max(0,\|q-\hat x\|-\epsilon)^2.$$

这些是误差界的数学出发点；实际代码还处理查询量化、均值偏移、cosine 的归一化及浮点保护项。
以候选下界 $L_i$ 排序后，若已得到 K 个精确结果，且下一候选的下界大于当前第 K 名距离，
即可省去该候选及之后候选的精确距离计算。等距情形沿用实现的比较语义。

下界筛选针对**已展开的候选集合**。图导航的量化估计、margin、扩展上限仍是近似搜索策略，
并不保证全库精确 Top-K。被过滤的节点不进入结果，但仍消耗扩展预算；硬上限独立于是否已找到 K 个结果。

## FP32 存储的内存优化：复用索引中的原始向量

原实现额外保存一份完整 FP32 `raw_arena_`。现在取消该副本，在精排时通过 `entity.get_vector`
取得原存储向量。每批最多4个所有权/固定页句柄一直保留到整批评分结束，兼容 mmap 和 buffer pool；
读取失败向上返回错误，cosine 的辅助存储字段仍交给原距离函数处理。

对只读快照，原向量与其逐字节副本是相同距离函数的相同输入。因此仅替换访问地址，不改变精排计算、
候选顺序或搜索预算，也没有新增有损量化。

取消的分配量为 $n\cdot\operatorname{align64}(4D_s)$，其中 $D_s$ 是含辅助字段的存储维度。
这表示省去的向量副本，不代表磁盘索引缩小或全部图数据的压缩比。

## 近零入口的桶范围

初始桶宽为 $w=\max(e,10^{-6})c$，其中 $e$ 是入口距离估计，$c$ 是配置系数。
队列有 $N=2048$ 个桶，正常正分数覆盖范围约为 $(N-2)w$。
若入口恰为查询或非常接近查询，$e\approx0$，普通邻居可能全部进入同一个 LIFO 溢出桶，丢失排序信息。
精排无法找回因此没有展开的节点。

修正仅在入口弹出、队列为空、首次邻居批次插入之前执行。令 $M$ 为该批有限正分数的最大值，设置

$$w'=\max\left(w,\operatorname{nextafter}\left(\frac{M}{N-3},+\infty\right)\right).$$

`N-3` 留出桶边界余量，向上舍入防止尺度不足；范围足够时保持原宽度。
此时没有待重定位条目，不增加扩展上限，不额外存储每节点数据。
它让首批正分数进入普通桶，不保证后续所有分数都不会溢出，也不把近似图导航变成全局精确搜索。

## 可选多视图旋转（RotationViews）

`QuantizedGraph.RotationViews` 支持 1/2/4，默认 1。该选项对 native、global、low_rank 三种 codec、
FP32/FP16 存储以及 cosine / squared L2 共用，不按数据集名称分流。
每个视图使用独立符号的 Hadamard 变换，拼接后按 `1/sqrt(views)` 缩放。
因此变换保持内积和范数，增加的是量化方向和编码长度，不改变原始向量维度、HNSW 图或精确重排距离。
768 维沿用 H12×H64 变换，其余维度沿用原有补零规则；每个视图都采用相同规则。

更多视图可降低量化误差，但会增加量化块大小、查询变换和邻居估距开销，并不保证所有数据集都更快。
低秩多视图模型在原始坐标系求特征向量，再变换到拼接空间，避免协方差内存随视图数平方增长。
单视图保留原有训练路径、随机序列和文件格式。

多视图使用 codec 内层 V2 和路由 V4，分别记录视图数；外层快照版本保持不变。
单视图仍使用原生空 codec 或学习 codec V1，以及路由 V2/V3。
加载仅使用索引中的元数据，不读取 `QG_RESEARCH_ROTATION_VIEWS`。不一致的路由、codec 或块尺寸会被拒绝。
旧版程序无法读取新的多视图模型；历史依赖环境变量生成的研究版索引应从原图重新构建，不能直接改名使用。
